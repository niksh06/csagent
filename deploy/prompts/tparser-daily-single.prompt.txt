TParser **daily digest** — single agent (no delegates). Produce the full daily digest in ONE run.
Window: **last 24 hours** — compute `WINDOW_START = now − 24h` (UTC), `WINDOW_END = now`.

Two tiers of output: a few **deep blocks** for what matters most, plus a one-line
**index** so the rest of the day is at least visible and clickable.

**Your entire final message IS the digest.** Its first character must be `📬`.
Everything you print is delivered to the user verbatim — a line like "Данные
собраны, ниже дайджест" is not a note to yourself, it is the first thing he reads.
Do not announce what you are about to do, do not explain deviations, do not
summarise your own process. If a rule below made you choose differently, just
choose — silently. Russian.

## Setup

1. `memory_get` name=`tparser-workflow` — tag/sphere rules and interests.

2. **API token.** It lives in `.env` in the working directory under `API_AUTH_TOKEN`.
   Read it into a shell variable and use it by reference — **never print it, never
   paste its value into a command**. It ends up in the transcript otherwise.

   ```
   TOKEN=$(grep -E '^API_AUTH_TOKEN=' .env | cut -d= -f2- | tr -d '"')
   curl -s -H "Authorization: Bearer $TOKEN" "http://127.0.0.1:8002/api/..."
   ```

3. **Fetch the window** — use `by-date-range`, paginated by `offset`:

   ```
   GET /api/posts/by-date-range?date_from=<YYYY-MM-DD>&date_to=<YYYY-MM-DD>&limit=200&offset=<N>
   ```

   - `date_from` = WINDOW_START's date, `date_to` = WINDOW_END's date + 1 day (covers the UTC boundary).
   - Response key is **`posts`** (not `items`).
   - Increase `offset` by 200 until a page returns fewer than 200 rows. Expect ~600–700 posts/day.
   - Then keep only posts whose `date` >= WINDOW_START.

   **No hydration step is needed** — `by-date-range` already returns `priority`,
   `topic_tags`, `category`, `summary`, `message`, `urls`, `urgency`.

   Do **not** use `/api/posts/recent-live`: its `after_rowid` is a forward
   live-tail cursor (`WHERE seq > ?` with `ORDER BY rowid DESC`), so paging
   backwards with it returns the same page forever. `/api/feed` is not needed either.

4. Bucket each post into **one** topic by `topic_tags` (else `category`, else summary
   keywords). A post belongs to at most one topic (highest-priority match).

## Topics (five buckets)

- **AI / ML / LLM** — AI, ML, LLM, benchmark, research, agent, RAG, fine-tuning
- **AISec / MLSec** — AISec, MLSec, LLM security, adversarial, jailbreak, prompt injection, model abuse
- **InfoSec / AppSec** — InfoSec, AppSec, security, vulnerability, CVE, exploit, malware, incident
- **Programming / devtools** — programming, devtools, language, framework, open source, library, IDE
- **DevSecOps / DevOps** — DevSecOps, DevOps, CI/CD, K8s, kubernetes, cloud, infra, SRE, terraform

## Selection — read this carefully, the counts must add up

**Tier 1 — deep blocks, ≤6 total.**
- First, **one block for every topic that has at least one post** (its highest-`priority` post).
  A topic with posts is never silent.
- Then fill the remaining slots (up to 6 total) with the highest-`priority` posts left over,
  regardless of topic.
- **One story per Tier 1.** If a post covers a story already shown in another block
  (the same incident/release reported by a second channel), skip it and take the next
  unique one. Six blocks about three stories is worse than six about six.

**Tier 2 — index, ≤35 lines total, ≤10 per topic.**
- Excluding posts already used in Tier 1.
- Allocate **round-robin across topics** — one line per topic per pass, each topic
  contributing its next-highest `priority` post — until you hit 35 lines or run out.
  Do **not** fill one topic to 10 before starting the next: a 6-post topic would be
  squeezed out entirely by a 170-post one.
- One line each. No verdicts, no bullets.

## Formats

Deep block (**≤500 characters each**):

```
### {channel_or_title} · `{priority}` · {primary_tag}
**Суть:** 1–2 предложения — главное утверждение, названные сущности.
**Вердикт:** 1–2 предложения — что это значит в разрезе tparser-workflow.
https://t.me/c/{short}/{post_id} · {best external URL or «нет URL»}
```

Index line (**≤105 characters each**):

```
`{priority}` {6–9 слов о сути} — https://t.me/c/{short}/{post_id}
```

`short` = str(channel_id) with a leading `-100` stripped. Never `t.me/@channel`.
Never use markdown link syntax for `t.me` links.

**Deep check** (optional, **≤2 per run**): for a Tier-1 post with an external http(s)
link and a thin summary, use `browser_navigate` + `browser_snapshot` (browser-ops) on
the one primary URL. Never invent content.

**Dedup:** window only; do **not** write `memory_fact_add` / `seen_post` facts. No Obsidian writes.

## Rules

- Russian. **TL;DR first**, immediately after the header lines.
- The header counts must be real: `{total}` = posts in window, `{deep_n}` = Tier-1
  blocks printed, `{index_n}` = index lines printed, `{offtopic_n}` = posts that
  matched none of the five topics. Do not round or invent them. `{offtopic_n}` is
  there deliberately: roughly a third of a day matches no bucket, and that should
  be visible rather than quietly dropped.
- If a topic has 0 posts: one line «нет релевантных постов» and no index section for it.
- Do not invent posts. Do not re-fetch the API beyond the steps above.

If all topics empty: `📬 TParser · день · {WINDOW_END} · релевантных постов не было.`
